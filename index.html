Rémi Couture · Games for Project Ares02

The short version

I have twenty-two working educational games for Ares. I would like to keep making them.

22games, each playable from briefing to debrief in a browser
318automated tests, all passing, covering the learning rules of every game
21different genres, from isometric strategy and SQL hunts to a card duel, a physics sticker pile and an orbital shooter
0ranges to spin up. Each game is a static bundle that embeds in a course page

What this is

Real training content, not mock-ups: authored scenarios, evidence, policies, queries, and a written explanation for every important mistake. The next pages quote it.

Why it matters to Ares

Missions need a live range. These need nothing. They give learners practice between missions, give sales a demo that runs anywhere, and fill slots the platform has already reserved for games.

What I am asking

Keep me on to take these from prototype to production with the games and content teams, and to keep building new ones. I have set out three ways to do that, including a half-time option.

Six remixes of the Games Hub

The hub games’ topics, rebuilt around a judgment twist.

RemixRemix ofThe twist
Pattern PatrolRegExile (games team)Regex as detection engineering: catch the attack, not the noise
Port AuthorityPortflow (games team)Ports by policy: allow, block or upgrade cleartext
Confidence BoardTrivialoot (games team)A six-category board with confidence wagers that reward calibration
Chain BreakerCylitaire: Kill Chain (games team)Rebuild an incident on the kill chain, then break it earliest
Tactic OrbitAstro-Defense (games team)Tag incoming techniques with their tactic to raise the shield
Blind SpotsThreat Modeler (games team)Place sensors on a budget; scored on how early each attack path is seen

Why remix

The hub games teach recall of frameworks well. Each remix keeps the topic and asks for a decision on top: a detection that must not over-fire, a confidence you must own, a chain you must break early.

How they were made

From each game’s topic and key art only. No code, levels, text or art copied, and every remix credits its original. They are an offer to the games team, not a replacement.

Game 1 of 22 · Isometric strategy

Network Defense: Keep Finance Online

Teaches: How routes and dependencies keep a service up, how to read evidence, and how to write an access rule that stops the attacker without stopping the business.

Evidence on screen“Source 198.51.100.23 is not on any approved list and is outside the company network.” “Destination: Finance — Remote desktop admin (RDP 3389).” “Pattern: repeated sign-in attempts, each with a different username.”
After a common mistake“You connected Finance straight to the Gateway. Invoices reached Finance, but Finance couldn’t reach its database on the Core server, so each one failed. Services depend on other services — a path from the internet isn’t enough.”
Final challenge, no hints“Which single rule best fits the policy?” Answer: DENY 203.0.113.200 → HR : Admin console

Why it sticks. The learner watches a rule succeed or fail on live traffic, so cause and effect are remembered together.

Where it fits Ares. Fits the reserved packet-gate and network-segmentation slots. Firewall and ACL rules are listed as untapped.

Game 5 of 22 · Dispatcher desk

Cyber Dispatch: First Shift

Teaches: Asking the questions that matter, giving the safe next step before harm lands, and handing off only what the evidence confirms.

Game 17 of 22 · Regex workbench · remix of RegExile

Pattern Patrol: Catch the Attack, Not the Noise

Teaches: Writing a detection that catches every attack line and none of its benign look-alikes: escaping, classes, alternation, quantifiers, boundaries.

A false alarm, on the line it hitsFailed password for administrator-training: “Contains ‘admin’ but is a training account.”
The fixFailed password for (root|admin)\b: the word boundary removes the noise.
The lesson on dots“In a regex a dot means ‘any character’. Escape it as \. when you mean a real dot, and use \b so .44 doesn’t also match .440.”

Why it sticks. Every false alarm shows on the exact line it hits, so precision stops being abstract.

Where it fits Ares. Log analysis and SIEM, listed as untapped. Credited remix of RegExile by the games team.

Why people remember it

Each game is built on how people learn, not on points and badges.

Retrieval practice

The learner produces the answer

They write the SQL, build the rule, place the alert, choose the fix. Producing an answer builds memory that reading and recognising do not.

Immediate, specific feedback

Every mistake explains itself

Feedback names the decision and the reason, at the moment it happens. Network Defense alone has about 19 explanation templates.

Safe failure

Consequences without damage

A wrong call queues a fraudulent payment or cuts off a working laptop, in fiction. The learner sees the cost, then gets to fix it.

Judgment, not recall of facts

Evidence before conclusion

Inspecting never classifies for you. Weak evidence never counts as proof. A correct conclusion without its evidence scores zero in Query Hunt.

Reflection

A debrief that replays your decisions

Choice, observed result, why, and how it connects to the mission. Network Defense rebuilds the exact moment from the command log.

Short and repeatable

Five minutes, different next time

Seeds and variants change traffic, attackers, the failing link, or which report is benign, so a replay is practice and not memorisation.

One rule runs through all twenty-two: the game score and the learning evidence are recorded separately. As one debrief puts it, “this record is evidence, not a grade.” That is what makes the result usable for reporting.

The hard part of a learning game is balance. I test it the way a game studio would.

How a new game gets made

  • Start from the skill. One learning objective, one decision the learner keeps getting wrong.
  • Find the mechanic that is the skill. If you can win without the knowledge, it is the wrong mechanic.
  • Write the content as data. Scenario, evidence, and an explanation for each mistake, in one reviewable file.
  • Prove the balance. Tests that show the lazy strategies lose and careful play wins.
  • Hand the SME a review sheet. Every objective and simplification, ready to approve or correct.
